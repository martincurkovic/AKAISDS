# Ensoniq ASR-X: engineering notes (moved out of AGENTS.md)

The detailed section that used to live in `AGENTS.md`, kept verbatim apart from this heading (AGENTS.md now holds a short pointer with the rules that must not be broken). Written 2026-10-20.

**Not covered by the EPS/ASR code**: no MIDI SDS; it speaks `F0 0F 10 01 <dev> <cmd>` and silently drops the ASR-10 dialect. Every wire fact and its confidence: `dev_docs/asrx-rom-findings.md` and the header of `core/asrx_sysex.py` (read before changing a byte). Sampler Type `ensoniq_asrx`, family `ensoniq`, `controller/asrx_transfers.py` (`AsrxTransfers`, chosen by `sampler_model` in `SamplerController._ensoniq`); fake `core/demo_asrx.py`, `tools/asrx_demo.py`, `tests/asrx_test_plan.md`. **Nothing has run on an ASR-X.**
- Dashboard only: LIST by `7E <dev> 05 04 <slot>` name requests (stops after `scan_empty_run` empties; `7F 41` = empty), RECEIVE the `SMP1` object (52-byte header + signed 16-bit BIG-ENDIAN samples) with command 04 range reads (fallback command 01), SEND (stereo = `NAME-L`/`-R`) with ONE command 02 message into the lowest free slot, then verify. **The rate lives in the header's pitch word** (+0x26), so nothing is resampled unless the target rate says so.
- **Free-slot rule (don't simplify):** a slot with no NAME can still hold something (recording buffers answer name requests "empty"), so a slot is accepted only if a range read gets SILENCE; an answer = in use, remembered in `engine.hidden`.
- **Device ID fallback** (first report, 2026-10-19: two name requests to ID 0, nothing back): if nothing answers, the slot scan asks ONCE as `7F` (all devices; read only), as does the hardware test; the reply's own ID is used for the session. **Uploads never go to 127.**
- **Never sent:** commands 05, 07, 10, 11, 12, 13, 15 (bank clears/replaces, a service jump) and command 02 with size 0 (clears a slot). A failed send can leave a half-written slot.
- **Logging is the debugging channel** (tester in another time zone): `AsrxTransfers:` lines (`AKAISDS_ASRX_TRACE=1` for every message), the 52-byte header hex and decoded at INFO, a stats line per op, a dump of the last 12 messages on failure. Keep those when refactoring.
- Left unknown on purpose: header bytes 0x18/0x19/0x1C/0x22/0x24 (constructor defaults), loops (not sent, not written to a received WAV), memory figure, the reply to a memory-full upload.
