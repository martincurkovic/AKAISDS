# Akai S900/S950: engineering notes (moved out of AGENTS.md)

The detailed section that used to live in `AGENTS.md`, kept verbatim apart from this heading (AGENTS.md now holds a short pointer with the rules that must not be broken). Written 2026-10-20.

A DIFFERENT protocol from the S1000 family: device byte `0x40`, function codes 0-11, 8-bit values as two MIDI bytes, 10-char ASCII names, XOR checksums, a sample dump that is ONE SysEx with 4-byte handshakes (`F0 7E code F7`; the standard 6-byte SDS ACK is silently ignored). Plan: `dev_docs/s950-support-plan.md`. **Nothing has run against hardware**; every guess is in `tests/s950_test_plan.md`. Ported from [s950tools](https://github.com/diemonster/s950tools) (MIT; notice in `src/ui/help/THIRD_PARTY_NOTICES.md`: keep it when porting more). `dxzl/akai-s950` has NO licence: don't copy it.
- `core/s950_sysex.py` and `core/s950_program.py` (76-byte header + 1-31 x 140-byte keygroups). Only the program HEADER offsets are pinned by real captures. Unmodelled bytes stay in `raw` and go back untouched. No delete opcode: don't invent one.
- **Own protocol family `"s950"`: nothing may fall through to the akai/generic branches.** `SamplerController` delegates to `controller/s950_transfers.py` and REFUSES the rest (`_s950_not_supported`).
- `S950Transfers`: ONE operation at a time; an RCAT reply is the "device ready" barrier before every upload. Uploads are open loop and ALWAYS go to an EMPTY slot (overwriting triggers a NAK storm), then the sample is named by SPRM read-modify-write. A receive streams a 4-byte ACK every 50 ms. Names uppercase, 10 chars, unique. Always 12-bit mono (stereo averaged), 200-475,020 words. Needs a MIDI INPUT. Unmeasured: a receive is one message up to ~1 MB, and a backend that splits long SysEx would lose it (`MidiManager._on_raw_message` drops fragments not starting with F0).
- **Editor** (`S950ProgramEditorWindow`; shares the Dashboard's controller, no `BridgeWorker`). **Writes are STAGED**: `write_program` does a fresh RPRGM, **refuses unless a `.syx` backup saved** (`~/.akaisds/s950_backups`), applies ONLY the changes onto the fresh copy, PRGM, NAK window, RPRGM read-back compare. It never creates a program or changes the keygroup count. Experimental warnings before the first Send and first write; "Write Program Back Unchanged (test)" is a tester's first step. Not done: create/duplicate/delete program, add/remove keygroups; renaming a sample doesn't rewrite programs using it.
- **Samples tab:** SPRM reads one at a time, only while the tab is active; audio arrives asynchronously into a temp WAV. **Only replay mode (O/L/A) and direction (N/R) can be WRITTEN** (Write / Revert are the WINDOW's bottom-bar buttons on the Samples tab; `write_sample_params`, result on `s950_sample_written`): fresh SPRM read, **no `.syx` backup (`sampleNN-NAME-<stamp>.syx`) = no write**, change ONLY those fields (`SAMPLE_WRITE_FIELDS`), NAK window, read back and compare; a no-change request sends nothing. **Status-bar messages stay short** (the "Experimental" label shares the bar): success/failure ends with `BACKUP_NOTE`, the full path goes to the log. Start, end, loop length, pitch and loudness stay read-only; markers locked.
- **s950tools says (read 2026-10-19, not reproduced):** SPRM write gets NO reply; some fields (**reverse for certain**) live in an "active edit buffer" refreshed only on re-select (ENT), so **a verified write can still need ENT** (our message says so). **Where a loop sits is NOT settled:** this app draws it over the last `loop_length` words before End; s950tools anchors it at Start. Decide by listening test before any loop/marker editor.
- **Sample EDITING (not built; analysis 2026-10-20):** an edit could only be a NEW sample (no delete, no overwrite of an occupied slot): the original stays until deleted on the panel and every edit permanently uses memory and a slot. Edits that bake into audio (Trim, Reverse, Fade, Normalise, Filter, Stretch / Pitch, Reverb, slices as samples) need no unknown SPRM semantics and reuse the shared maths; start/end/loop editing waits for the loop test; program creation from slices isn't built. A "rename swap" (send under a temp name, SPRM-rename the original to `NAME-OLD`, rename the edit) works only IF renaming an occupied slot does: unproven. **Build only after a tester confirms receive, send and naming** (`tests/s950_test_plan.md` A-C). Write-up: `dev_docs/s950-sample-editing.md`.
- Pitfalls: a standard SDS ACK on channel 0 (`F0 7E 00 pp F7`) collides with the S950's request-sample-dump: never test Generic SDS on an S950 casually. `QListWidget.clear()` defers deleting row widgets: tests that repopulate lists must flush deferred deletes (the `dashboard` fixture does).
