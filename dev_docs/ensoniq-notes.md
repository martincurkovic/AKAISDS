# Ensoniq EPS/EPS-16+/ASR-10: engineering notes (moved out of AGENTS.md)

The detailed section that used to live in `AGENTS.md`, kept verbatim apart from this heading (AGENTS.md now holds a short pointer with the rules that must not be broken). Written 2026-10-20.

No tester yet; an experimental build is planned for forum testers. Research: `dev_docs/ensoniq-support-plan.md`; spec corrections (read before coding): `dev_docs/ensoniq-spec-crosscheck.md`. The specs are copyright and not in the repo. Code: `core/ensoniq_sysex.py`, `core/demo_ensoniq.py` (`FakeEnsoniq`: same reading of the spec as the engine, so it catches our inconsistencies, not a misreading), `controller/ensoniq_transfers.py` (list, receive, send), Sampler Type `ensoniq_eps_asr`, `tools/ensoniq_demo.py`, `tests/ensoniq_test_plan.md`.
- **Own protocol family `"ensoniq"`: nothing may fall through to the akai/generic branches.** `SamplerController` delegates list, receive, send, incoming SysEx and cancel to the engine and REFUSES the rest (`_ensoniq_not_supported`); the Dashboard disables Delete/Edit/Open Editor and warns once before the first send; Settings > Run Hardware Test sends the MIDI identity request then ONE GET INSTRUMENT 0 (one outstanding, only a RESPONSE or PUT accepted so a DAW's echo is ignored).
- **Engine:** ONE GET conversation at a time (RESPONSE ACK -> PUT's first message, ACKed within 2 s -> data-only message, ACKed; no retransmit, so a damaged message is NAKed and the GET repeated). Errors are RESPONSE statuses (05 = instrument absent is normal). No list command: the list is PROBED (GET INSTRUMENT 0-7, GET LAYER 0-7, GET WAVESAMPLE PARAMETERS for each number in the layer's key map). The Dashboard "sample number" is `pack_number(instrument, layer, wavesample)`. Audio `[start, end)` in `chunk_words` pieces (end may be inclusive; both accepted). Needs a MIDI input and a Device ID 0-15. Memory bar: free blocks + each instrument's size, 256 words a block (GUESS); a zero total = unknown.
- **Sending (WRITES, the most guessed part):** each file becomes a NEW instrument in the first free slot (an existing one is never touched), one layer per channel (stereo = two layers, Pan 1 / 8, unverified), one wavesample per layer: free-blocks check -> CREATE INSTRUMENT -> CREATE LAYER -> GET/PUT parameters -> TRUNCATE -> PUT WAVESAMPLE DATA in `put_chunk_words` pieces -> GET/PUT parameters (start 0, end `len + end_adjust` (-1), loop) -> [pan] -> read back. **Never PUT INSTRUMENT / PUT LAYER** (they carry RAM pointers). A failed send can leave a half-built instrument; nothing deletes it (`_partial_note`). Rates are a CODE (period = code x 1.6 us): audio is resampled to the nearest (44.1 kHz -> 44,643 Hz); over 1,048,575 words is refused. Tester knobs: `pace_ms`, `put_chunk_words`, `truncate_placeholder`, `end_adjust`, `put_end_inclusive`, `silent_wait_ms`.
- **A real unit must confirm** (the fake shares these): PUT WAVESAMPLE DATA at the current length grows the wavesample, TRUNCATE after the first parameter write, end written one short, the Pan values, the channel byte (base channel or Device ID), the rate code.
- Never put `ensoniq_sysex.NEVER_SEND` (delete instrument/layer/wavesample, SAVE INSTRUMENT) on the wire. The offset `00 00 40 00` in two specs is a typo (`00 00 08 00`); a parameter number is ONE 12-bit word.
